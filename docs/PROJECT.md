# Smart Lava Lamp Controller: Project Documentation

## 1. Goals
Retrofit a 12 V DC lava lamp (heater about 12 V / 1.95 A, about 23 W, coil about 6-7 Ω) with:
- closed-loop PID control of glass base temperature (45-55 °C)
- NTP-synced schedule with predictive warm-up
- local web dashboard (REST + WebSocket), token protected, no cloud
- scripted temperature patterns
- 16-LED WS2812B status ring

## 2. Decisions (from review)
| Topic | Decision |
|---|---|
| MCU | **ESP32-C3 SuperMini**, MicroPython |
| Heater | 12 V, 1.95 A. Not hazardous when left powered, by lamp construction. Software safety is still kept as defence in depth |
| Level shifter, thermal fuse | Not used |
| Timezone | Europe/London and Europe/Lisbon: UTC+0, UTC+1 in summer (see 6.3) |
| Web auth | Shared token (lamp lives on the IoT WLAN) |
| Updates | USB only (`mpremote`), no OTA |

## 3. Power budget
| Rail | Load | Current |
|---|---|---|
| 12 V | Heater at 100 % duty | 1.95 A |
| 12 V (via buck) | 5 V side: LED ring (max 0.96 A) + MCU (about 0.15 A) at about 90 % efficiency | about 0.5 A |
| **Total at 12 V, worst case** | | **about 2.5 A** |

A 12 V supply rated 3 A is recommended. The 2 A rating in the spec leaves little margin. The code caps LED brightness (default 40 %, about 0.4 A at 5 V) and heater duty is limited by the PID, so typical draw is lower.

## 4. Pin map (ESP32-C3 SuperMini, proposed)
Verify against your board's silkscreen before wiring. Avoid strapping pins 2, 8 and 9 for external peripherals.

| Function | GPIO |
|---|---|
| Heater MOSFET gate (via 220 Ω) | GPIO4 |
| DS18B20 data | GPIO5 |
| WS2812B ring data | GPIO6 |
| Onboard blue LED (active low) | GPIO8 |

All pins live in `firmware/pins.py` only.

## 5. Hardware
### 5.1 Circuit
```
12V+ ──┬─ 100µF ─ GND
       ├─────────── Heater ──┬── Drain (IRLZ44N)
       │                     └── 1N4007 across heater (stripe to 12V+)
       └── Buck IN                 Source ── GND
Buck OUT 5V ── ESP32-C3 SuperMini 5V pin, WS2812B ring 5V
ESP32 3V3 ──┬─ 4.7kΩ ─┬─ DS18B20 DATA ── GPIO5
            └─ DS18B20 VDD   (GND to common GND)
GPIO4 ── 220Ω ──┬── Gate
                └── 10kΩ ── GND
GPIO6 ── (optional 100-330Ω) ── Ring DIN
```
All grounds join at one point.

### 5.2 Notes
- IRLZ44N is logic-level. IRF540/IRF740 will not work at 3.3 V drive.
- At 1.95 A the MOSFET dissipates under 0.15 W, so no heatsink is needed.
- WS2812B data at 3.3 V from a 5 V ring usually works. If the ring flickers, add a 74AHCT125 or put a diode in series with the ring's 5 V supply to lower its logic threshold (optional, not required by default).
- Do not connect USB and the buck's 5 V at the same time unless a Schottky diode is in series with the buck output. Either unplug 12 V when flashing, or add the diode.
- Add a 100 nF capacitor across the ring supply and a 330-470 µF capacitor near the ring if you see glitches.

### 5.3 BOM
As in the original spec, with the MCU changed to the ESP32-C3 SuperMini. Optional extras: 1 Schottky diode (1N5819), 1 x 100 nF capacitor, a 3 A supply.

## 6. Firmware design
### 6.1 Modules
`boot.py`, `main.py`, `config.py`, `pins.py`, `sensor.py`, `heater.py`, `pid.py`, `safety.py`, `thermal.py`, `patterns.py`, `scheduler.py`, `leds.py`, `web/`. See the implementation plan for the responsibilities of each.

### 6.2 Control and safety
- Single asyncio loop. The PWM is generated by the LEDC peripheral, so the heater keeps running through GC pauses and network activity.
- PID runs at 1 Hz, with the sensor read every conversion cycle. Output is clamped to 0-100 %, with anti-windup and derivative on measurement.
- Safety latch, trips on: temperature of 65 °C or more, sensor missing / CRC error / reading exactly -127 or 85.0 °C, or no valid reading for 5 s. It sets duty to 0 and latches. The latch clears by reboot or by `POST /api/reset-fault` once the temperature is safe.
- Hardware watchdog (`machine.WDT`, 8 s) is fed only by the control loop.
- `boot.py` forces the heater pin low before anything else.

### 6.3 Time
NTP via `ntptime`, resync every 6 h. Offset is applied by a small function: UTC+0, plus 1 h from 01:00 UTC on the last Sunday of March until 01:00 UTC on the last Sunday of October. London and Lisbon share these rules, so it is a few lines of code and not a fixed offset. A plain fixed UTC+0 would be an hour wrong all summer. If you really want fixed, set `tz_dst=false` in config.

If NTP has not synced, scheduled heating does not start (manual control still works).

### 6.4 Predictive warm-up
`lead = (target - ambient) / heat_rate`. The initial `heat_rate` is estimated (default lead 45 min) and updated with an exponential average after each completed warm-up. Stored in config at the end of a warm-up only, to limit flash writes.

### 6.5 States
`OFF` → `WARMING` → `HOLDING` → `COOLING` → `OFF`, and `FAULT` from anywhere. `MANUAL` is `HOLDING` started from the app.

### 6.6 Configuration (`config.json`)
```json
{
  "wifi": {"ssid": "", "password": ""},
  "token": "change-me",
  "hostname": "lavalamp",
  "setpoint": 50.0,
  "pid": {"kp": 8.0, "ki": 0.05, "kd": 40.0},
  "max_duty": 100,
  "limits": {"min": 45, "max": 55, "cutoff": 65},
  "tz_dst": true,
  "led": {"brightness": 40, "palette": "lava"},
  "schedule": [{"days": [0,1,2,3,4], "start": "18:00", "end": "23:00", "pattern": "calm"}],
  "patterns": {"calm": [[0, 50]], "lively": [[0, 54], [20, 48], [40, 54]]},
  "heat_rate": 0.15
}
```
PID gains are starting values only and must be tuned on the real lamp. The token is never returned by the API.

## 7. REST and WebSocket API
All requests need `Authorization: Bearer <token>`. The WebSocket takes `?token=`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/status` | temp, setpoint, duty, state, fault, time, ip, rssi |
| POST | `/api/power` | `{"on": true}` start or stop heating |
| POST | `/api/setpoint` | `{"value": 50}`, clamped to limits |
| GET/POST | `/api/pid` | read or write gains |
| GET/POST | `/api/schedule` | list or replace schedule (validated) |
| GET/POST | `/api/patterns` | list or replace patterns |
| POST | `/api/pattern/run` | `{"name": "calm"}` or `{"name": null}` to stop |
| GET/POST | `/api/led` | brightness, palette, on/off |
| GET | `/api/log` | ring buffer of about 360 samples |
| POST | `/api/reset-fault` | clear latch if safe |
| POST | `/api/wifi` | set credentials, then reboot |
| WS | `/ws` | 1 Hz telemetry: `{t, sp, duty, state}` |

Errors: `401` bad token, `400` validation (JSON message), `409` action not allowed in the current state.

## 8. LED behaviour
| State | Display |
|---|---|
| WARMING | Sweep fill, lit LEDs = progress × 16, colour shifts blue → orange |
| HOLDING | Breath, rate and brightness follow duty %, palette colour |
| COOLING | Slow fade to off |
| FAULT | Red pulse |
| No Wi-Fi / AP mode | Cyan chase |

## 9. Testing
- Host `pytest`: PID, scheduler (incl. DST boundaries), pattern interpolation, config validation.
- `tools/sim.py`: first-order plant with delay for tuning.
- On hardware: the Phase 1-5 acceptance criteria in the implementation plan.
